# Android TWA Release Runbook

Étude on Android is packaged as a **Trusted Web Activity (TWA)** pointing at the live PWA (`https://maurs9.github.io/etude/etude.html`). Because the TWA uses Chrome's engine and Étude's service worker (`sw.js`), every push to `main` automatically updates both the Web app and the Android app without rebuilding the APK.

You only need to trigger a new Android release when changing native wrapper settings (`android-twa/twa-manifest.json`), app icon, or version metadata.

---

## 1. One-time setup: Signing keystore & GitHub Secrets

Generate a release keystore **once** on any machine with Java (`keytool`) installed. On Windows, if `keytool` is not installed yet, install Temurin JDK 17 first (`winget install EclipseAdoptium.Temurin.17.JDK`, then reopen your terminal):

```sh
keytool -genkeypair -v \
  -keystore etude-release.keystore \
  -alias etude \
  -keyalg RSA -keysize 2048 -validity 10000
```

Encode it to base64 (single line) and keep `etude-release.keystore` backed up safely outside the repo:

```sh
# Linux / macOS / Git Bash
base64 -w 0 etude-release.keystore
```

```powershell
# PowerShell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("etude-release.keystore")) | Set-Clipboard
```

Add these secrets in **GitHub → Settings → Secrets and variables → Actions**:

| Secret | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | Base64 string of `etude-release.keystore` |
| `ANDROID_KEYSTORE_PASSWORD` | Keystore password |
| `ANDROID_KEY_PASSWORD` | Key password (often the same as keystore password) |
| `ANDROID_KEY_ALIAS` | `etude` (optional; defaults to `etude`) |

## 2. Build & publish an Android release

Check out the commit you want to build and create a fresh version tag. Pushing it starts the release workflow.

```sh
git tag v1.0.24
git push origin v1.0.24
```

For a manual run at the pushed tag, use `gh workflow run android-release.yml --ref v1.0.24`. To dispatch from a branch in the GitHub Actions UI, enter the version explicitly and make sure the branch tip is the commit at the pushed tag.

The Android `versionCode` defaults to the workflow run number. It must be higher than the previous APK or AAB's code. Manual runs can supply an explicit `version_code`. The release checks that it exceeds every prior Android release code and publishes the code alongside each build. For older releases the check reads the APK metadata. If the run number is too low, dispatch the tag with a higher code.

The workflow verifies that the pushed tag points to the checkout before signing and again before publication. It rejects an existing GitHub Release for that tag. To publish replacement binaries, create a new version and tag.

The workflow creates a GitHub Release containing:
- `etude-android-v1.0.24.apk` (for direct install on Android)
- `etude-android-v1.0.24.aab` (for Google Play)
- `assetlinks.json` (generated with your key's SHA-256 fingerprint)

## 3. Remove the Chrome address bar (`assetlinks.json`)

Because Étude is hosted under `/etude/` on `maurs9.github.io`, Android checks Digital Asset Links at the **domain root**:
`https://maurs9.github.io/.well-known/assetlinks.json`

1. Create the user-site repository **`Maurs9/maurs9.github.io`** (if it doesn't exist yet) with GitHub Pages enabled.
2. Add an empty `.nojekyll` file at the root of `Maurs9/maurs9.github.io` (so GitHub Pages does not ignore `.well-known/`).
3. Copy the `assetlinks.json` generated by the Release workflow into `Maurs9/maurs9.github.io/.well-known/assetlinks.json`.
4. Verify in a browser that `https://maurs9.github.io/.well-known/assetlinks.json` returns JSON. Once live, re-open the Android app and the Chrome toolbar will disappear.
