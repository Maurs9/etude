# Local translation feasibility and completeness audit

Scope: investigation only; no translations generated, no user data uploaded, no application files or existing translations edited. Results apply to this machine and source revision when tested (2026-11-06).

## Availability and limitations

- Python has CTranslate2 4.8.3 and SentencePiece. CPU supports float32, int8 and int8_float32. CTranslate2 reported zero CUDA devices despite `nvidia-smi` reporting a GTX 1650 Ti with 4096 MiB. RAM reported 16,505,847,808 bytes. No speed or translation-quality measurement was possible without a model.
- No `ollama`, `llama-cli`, `llama-server`, `lms`, or `lmstudio` command was on PATH. No local inference service was observed on ports 11434, 1234, 8080, or 8000. Common Ollama, LM Studio, Hugging Face and Argos model locations and selected common caches were empty or absent. This is not an exhaustive machine-wide model search. `transformers`, `torch`, `llama_cpp` and `argostranslate` were not importable in the active Python environment.
- The current assistant provider is remote. A local proxy or credential does not make a remote inference backend private. No credentials were inspected, tested against remote providers, or sent anywhere. Do not submit source text, excerpts from user files, MIDI, scores, settings, or data to a cloud model under the requested no-upload constraint.
- An offline CTranslate2 model plus compatible tokenizer is a plausible batch-MT path, but no usable local checkpoint or tokenizer assets were identified. A model download would retrieve model assets, not upload application text; it needs prior authorization, sufficient storage, provenance and license review. NLLB-200 600M is one candidate for experimentation, not a recommendation to ship: its card specifies CC-BY-NC and research use, so suitability for distribution/commercial use is a blocker. Check the actual model's license independently. CTranslate2 provides CPU batch translation but requires correct model-specific preprocessing and target-language tokens. Sources: https://opennmt.net/CTranslate2/translation.html and https://huggingface.co/facebook/nllb-200-distilled-600M.
- Another offline option is a separately installed local LLM/model with a compatible local runner, but neither was verified here. Benchmark both candidate MT and LLM against a bilingual musician-reviewed gold set before choosing. The installed assistant or nominal cloud credentials are not evidence of a usable private local model. Human authoring with a local translation memory and native review avoids the model prerequisite, but reviewer availability and effort were not verified.

## Observed source coverage

`node i18n-framework/inventory.cjs` currently extracts 1,354 dictionary keys, 22 lesson records, 8 units, 55 glossary entries, 22 quiz sets, 22 summary sets and music data: 24 intervals, 19 scales, 25 chords, 4 categories, 6 inversions, 17 feels and 12 song groups. These are entry counts, not proof all displayed text is captured.

Known omissions or integration gaps that a complete inventory must address:

1. `PIECES` titles, generated/excerpt titles and bar labels, including two direct English/Romanian code paths at `etude.html:6620,6628` and excerpt construction at `9219-9222`.
2. `ACCOMP_PATTERNS` (six bilingual pattern names) and `PROGS` / `ACCOMP_PROGS` names, directly shown at `9864-9865`; preserve their identifiers and musical behavior.
3. Hardcoded en/ro branches for music descriptions and song hints (`2884-2905`), compound interval grammar (`3244`), whole/half step names (`6243`), locale-sensitive list/number/date formatting (`7230`, `8621`, `9593`), and any dynamic strings. Manually review all branch matches: a lexical search after `const STRINGS` found 24 `lang === 'en'/'ro'` comparisons and four `[lang] ||` fallbacks; this is not a complete parser or semantic inventory.
4. Static DOM text/attributes not marked for i18n, dynamic DOM creation and templates, aria labels/live regions, generated SVG titles, import/export flows, formatting/pluralization, and fixed musical strings need a DOM/code review with an explicit non-translatable allowlist. Never treat user-supplied score metadata as app-owned text to translate.
5. Existing tests compare runtime strings, lessons and music only. They do not verify rendered glossary, units, quizzes, summaries, pieces, accompaniment, generated excerpts, all accessibility labels or every interaction. Existing payload validator is structural, not a linguistic or runtime proof. `--audit` sees 445 distinct `data-i18n*` keys, 487 literal translation-call keys, 113 dynamic-call matches and no unresolved static keys; the scanner is best-effort, has false positives/negatives, and zero unresolved static keys is not app-wide completeness.

## Practical fail-closed workflow

1. Freeze a source revision and export all app-owned text, including the omitted families above, into a stable keyed manifest with locations, screen/context, translatable text and immutable identifiers. Generate exact sets from source, not a handwritten expected total. Inventory all 22 lessons and all other families per locale; do not overwrite existing translations.
2. Store each locale independently in staging with per-entry source hash, state (`untranslated`, `draft`, `reviewed`), translator/reviewer and glossary version. Reuse identical text only where meaning/context agrees. Changed source hashes invalidate approval. Keep blanks missing, not English fallbacks. Treat source-identical names and notation as explicit reviewed exceptions.
3. Establish a musician-reviewed per-language terminology/style sheet, including note systems and German B/H, and a gold set covering ambiguous notes, accidentals, scales, intervals, chords, meter, placeholders, and prose. Independent bilingual human review is a release requirement, including every chapter, glossary/quiz answer and other content. Automated back-translation or model agreement may flag errors but cannot certify musical or linguistic quality.
4. Once an appropriately licensed local model and tokenizer are present, run fully offline with networking disabled and small context-aware batches keyed by stable IDs; extract only text nodes/declared translatable attributes and reconstruct markup mechanically. Preserve placeholder multisets, links, demos, IDs and functional attributes. Quarantine malformed output and all English fallback; never auto-publish MT. Audit separately for unmodified strings that are valid shared names/symbols versus untranslated English.
5. Expand validator to exact source/target key parity, 22 chapter IDs, all new categories, markup/functional attributes, `%s`/`%a`/`%b`, repeat/number alignment and source-hash review status. Dynamic branches require behavior tests, not regex alone. Compare answers/quiz correctness and all values against approved content.
6. Run file-mode Playwright with networking blocked; iterate all seven locales and notation options without coupling them, including language switches/reload, chapters, glossary/search, every quiz and summary, pieces, accompaniment, generated excerpts, a11y, responsive layout, import/export and fallback instrumentation. Distinguish intentional names from English fallback. Require all validators, per-locale native review and tests to pass before exposing a locale.

## Tests actually executed

- `python -B -m unittest discover -s i18n-framework -p 'test_*.py' -v`: 7 passed.
- `python -B i18n-framework/validator.py --audit`: static keys missing 0; 113 dynamic matches remain manual review.
- Validating existing draft files against this framework schema fails: de 2,018 issues, fr 1,989, it 2,170, es 2,020, pt-BR 2,062. These are validator issue counts, not precise counts of untranslated source strings; schema differences and unknown fields contribute. No draft should be enabled.
- Default Playwright `chrome` channel: all six tests failed at browser launch because Chrome was not installed at the configured path. With `PW_CHANNEL=msedge npx playwright test --config=i18n-framework/playwright.config.cjs`: one English/Romanian file-mode reload/notation test passed, five target-locale tests were skipped because `ETUDE_LOCALE_PAYLOAD_DIR` was unset. No target locale was proven complete.
- No local model inference was performed; no linguistic accuracy, throughput or end-to-end target-locale quality is claimed.
